# Dataset selection

Status: research record, retrieval date **2026-11-12**. No dataset bytes were downloaded. Decisions below are about what the project is allowed to use once a download is explicitly approved.

Sources checked: Hugging Face dataset APIs and dataset cards, the Datasets Server statistics endpoint where it responded, the NVIDIA laptop specification page, and the StarCoder2 paper page for descriptions of data that are not themselves a license grant. License statements are quoted or paraphrased only from those pages. Where a card does not state a license, this file says so.

## Decision

| Role | Source | Decision |
| --- | --- | --- |
| Pretraining and tokenizer | `codeparrot/codeparrot-clean-train` | **Selected, download still disabled.** Stream it. Keep only the seven permissive license labels listed below. |
| Validation language-model data | `codeparrot/codeparrot-clean-valid` | **Selected as held-out data.** Never tokenize the vocabulary on it. Never train on it. |
| Multilingual pretraining | The Stack v2 and StarCoder2 file dumps | **Blocked.** Gated, extra Software Heritage terms, and the inspected Hub schemas do not contain file contents. |
| Extra code | `code-search-net/code_search_net` | **Excluded from pretraining.** Per-example license is absent. Also a poor file-level language-model corpus. |
| Instruction tuning | Magicoder-Evol-Instruct-110K, Code-Feedback, CodeAlpaca-20k | **Future SFT only.** Public and licensed at the dataset-card level. Out of the base-model corpus. |
| Evaluation | HumanEval, MBPP, EvalPlus | **Test-only, later.** Do not train on any split. |

Initial mixture that this decision can actually support:

| Language | Planned share of the first corpus |
| --- | ---: |
| Python | 100% |
| JavaScript, TypeScript, Java, C, C++, Go, Rust, SQL, Bash | 0% until a reviewed source exists |

The 70 / 15 / 10 / 5 sketch in the project brief is a target for a later corpus. Using it now would report languages the training set does not contain.

The combined repository's card shows a single split of 5,361,373 rows. Training on that repository would mix the validation files into the training stream. Use the two split repositories.

The validation card's prose says "Train split of CodeParrot Dataset Cleaned." That sentence is wrong relative to the repository id and the row count. The Hub split **inside** `codeparrot-clean-valid` is named `train`. Loaders must key off the repository id, then request split `train`.

### Schema

Confirmed on the train and valid cards, and on the Datasets Server info for the train repository:

`repo_name`, `path`, `copies`, `size`, `content`, `license`, `hash`, `line_mean`, `line_max`, `alpha_frac`, `autogenerated`

Types from the Datasets Server info: strings for `repo_name`, `path`, `copies`, `size`, `content`, `license`; `int64` for `hash` and `line_max`; `float64` for `line_mean` and `alpha_frac`; `bool` for `autogenerated`. `copies` and `size` are strings, not numbers.

Cleaning already claimed by the card:

- exact-match deduplication
- average line length under 100
- maximum line length under 1,000
- alphanumeric fraction above 0.25
- keyword removal of auto-generated files

The partial index below has `autogenerated = false` for every indexed row. The project still records the field and drops a row if it is true.

### License

### Size estimate for the permissive subset

Indexed content length: minimum 666 characters, median 4,608, mean 10,361, maximum 1,026,903. Those numbers describe the 477,028-row index only.

If both the 60.01% permissive ratio and the 10,361-character mean applied to all 5,300,000 train rows, the kept text would be about **33 GB** and about **8.2 billion tokens** at 4 characters per token. A 32k byte-level BPE on code often lands near 3.5–4.5 characters per token. The tokenizer's own length report has to replace this guess.

33 GB of permissive text would be enough for one Chinchilla pass of the 168M model (3.36 billion tokens) if the extrapolation holds. Confirm with a streaming count before scheduling a multi-day run.

### What we will not use from the CodeParrot organization yet

The organization page also lists near-deduplicated releases, including `codeparrot/codeparrot-train-near-deduplication` (the dataset page reports 3,556,778 rows) and a validation near-dedup repository whose page reports 110,960 rows. 110,960 is larger than the official 61,373-row validation split, and the validation card text repeats the train-split description. Those repositories stay unused until someone inspects them. Exact hashes plus our own MinHash on the permissive subset are the dedup plan.

`codeparrot/github-code` is described by the organization as about 1 TB across 32 languages. It is out of scope for this disk and has not had a license review in this audit.

### Split and leakage rules

- Tokenizer training reads the permissive train stream only.
- Validation reads the permissive slice of `codeparrot-clean-valid` only.
- Intersect `repo_name` between the kept train files and the kept validation files. Drop colliding repositories from training and record them.
- HumanEval and MBPP strings are evaluation data. Before a meaningful pretraining run, exact-match filter those prompts and reference solutions out of the train stream. CodeParrot was collected from GitHub around 2021–2022 (repository created 2022-03-02). Overlap is possible even though HumanEval was written to avoid the Codex training set.

### Storage plan

| Pull | Cap | When |
| --- | --- | --- |
| Pipeline sample | 20,000 kept permissive train files | First time a download is approved. A few hundred MB at the indexed mean length. |
| Tokenizer and experimental corpus | up to about 2 GB of kept text | After the pipeline sample's license log looks right |
| Meaningful pretraining corpus | up to about 20 GB of kept text, or 4 billion tokens, whichever comes first | Only after a measured training throughput and a license census |

Do not download the 27 GiB compressed train repository onto this machine as a mirror. Stream and stop at the cap. Leave at least 40 GB of the current 131 GB free.

## The Stack v2

| | |
| --- | --- |
| Repository | `bigcode/the-stack-v2` |
| API `gated` | `"auto"` |
| Card license | `other` |
| Hub `usedStorage` | 426,977,114,770 bytes (397.7 GiB) |
| Configs | 659 language configs plus a default, parquet under `data/<language>/` |
| Last modified | 2026-08-03 |
| Paper | arXiv:2402.19173 |

The gate prompt on the model card, retrieved with the dataset API, requires all of the following before use:

1. Bulk download needs an agreement with Software Heritage and Inria. Contact `datasets@softwareheritage.org`.
2. Training use must follow the Software Heritage principles for language-model training. Those principles were **not** fetched in this audit.
3. Each file remains under its original license, including attribution terms. Provenance is provided so callers can comply.
4. The dataset is updated for removal requests. Accessing it includes an agreement to move to the latest usable version.
5. Access shares the caller's email and Hugging Face username with the maintainers.

Related repository `bigcode/the-stack-v2-train-smol-ids`:

| | |
| --- | --- |
| Gated | `"auto"`, same terms |
| License tag | `other` |
| `usedStorage` | 33,367,129,513 bytes (31.1 GiB), 64 parquet shards |
| Schema | Repository records. Each repository has a list of files with `blob_id`, `path`, `content_id`, `detected_licenses`, `license_type`, language, vendor and generated flags, and line statistics. **No file-content field.** |

The Stack v2 Hub release inspected here is an identifier and metadata index. Source bytes are retrieved from Software Heritage by content id. That is the bulk-download step the gate points at. 398 GiB of metadata already exceeds the 131 GB free on this disk, before any source file is stored.

StarCoder2's paper describes `the-stack-v2-train-smol` as about 525.5 billion tokens across 17 programming languages (C, C#, C++, Go, Java, JavaScript, Kotlin, Lua, PHP, Python, R, Ruby, Rust, SQL, Shell, Swift, TypeScript) plus documentation formats. That scale is a reference point. It is not a corpus this machine can store or train on.

`license_type` on this dataset includes permissive and `no_license` files. StarCoder2 trained on both. This project quarantines missing licenses. A later approval would still drop `no_license` rows.

**Decision: do not request access and do not download.** Revisit only if the Python-only corpus is actually too small after the license census, and only after the Software Heritage terms have been read and accepted by the user.

## StarCoder2 training files

Organization page: <https://huggingface.co/starcoder2data>

The public organization text lists:

| Name | Described contents |
| --- | --- |
| `the-stack-v2-train-full` | 600+ languages, files concatenated per repository, used for StarCoder2-15B |
| `the-stack-v2-train-full-files` | Same data, one file per row |
| `the-stack-v2-train-smol` | 17 languages, repository-concatenated, used for the 3B and 7B models |
| `the-stack-v2-train-smol-files` | Same data, one file per row |

Anonymous API listing of `author=starcoder2data` returned an empty list. Direct requests for `starcoder2data/the-stack-v2-train-smol-files` and the Stack v2 README URL returned **401 Unauthorized**. The file-bearing training dumps are not publicly readable from this environment.

**Decision: blocked.** They are the right long-term multilingual candidate if access is granted and a small permissive, content-bearing subset can be streamed under the cap. They are not part of the first corpus.

## CodeSearchNet

| | |
| --- | --- |
| Canonical id | `code-search-net/code_search_net` |
| The id in the brief | `code_search_net` resolves to that repository in the Hub API |
| Gated | No |
| Card license | `other` |
| Download size, `all` config | 1,963,220,197 bytes |
| Dataset size, `all` config | 6,433,783,930 bytes |
| Hub `usedStorage` | 9,043,417,317 bytes |
| Languages | Go, Java, JavaScript, PHP, Python, Ruby |
| Train / validation / test examples, `all` | 1,880,853 / 89,154 / 100,529 |

Schema is function-level: `repository_name`, `func_name`, `whole_func_string`, `func_code_string`, `func_documentation_string`, token lists, `split_name`, `func_code_url`. There is no license column.

The card's licensing section says each example comes from a GitHub repository with its own license, and that example-wise license information is not included. The collection notes say repositories with no license, or with a license that does not allow redistribution of parts, were removed at build time. That is a dataset-level claim. It is not a per-row license this project can record. Missing per-row metadata is quarantined.

The corpus is also the wrong shape for the first language-model run: documented functions only, with constructors and tests removed, and with an official test split that would be easy to leak.

**Decision: excluded from pretraining.** It can be reconsidered for a later docstring-conditioned task if licenses are joined back from repository metadata. The test split is never training data.

## Evaluation datasets

Not downloaded. Not training data, including splits named `train`.

| Repository | Card license | Split to evaluate | Size |
| --- | --- | --- | --- |
| `openai/openai_humaneval` | `mit` | `test`, 164 problems | dataset size 194,394 bytes |
| `google-research-datasets/mbpp` | `cc-by-4.0` | `test` of the `sanitized` or `full` config. The `full` test split has 500 problems. The `full` train split has 374 problems and is still benchmark material. | under 100 MB on the Hub |
| `evalplus/humanevalplus` | `apache-2.0` | `test`, 164 problems | download about 2.9 MB on the card |
| `evalplus/mbppplus` | `apache-2.0` on the dataset page | test problems, page reports 378 rows | about 1.13 MB on the page |

HumanEval features: `task_id`, `prompt`, `canonical_solution`, `test`, `entry_point`.

MBPP `full` features: `task_id`, `text`, `code`, `test_list`, `test_setup_code`, `challenge_test_list`.

BigCode Evaluation Harness (`bigcode-project/bigcode-evaluation-harness`, GitHub license Apache-2.0, retrieved 2026-11-12) can run HumanEval, HumanEval+, MBPP, and MBPP+. It expects a Hugging Face causal LM. This project's from-scratch checkpoint will need a thin adapter. The first functional eval should be an in-repo runner: parse with `ast`, then execute in a subprocess with resource limits. Docker and Podman are not installed on this machine. A container runtime should be added before generated code from a real checkpoint is executed. A restricted subprocess is the interim isolation, and reports should say that.

## Governance artifacts to produce once data is approved

These files do not exist yet. The pipeline phase creates them from the run that actually reads data:

- `data/dataset_manifest.yaml` — repository id, revision when the Hub provides one, retrieval date, role, caps, hash of the config
- `data/reports/license_report.json` — counts for allowed, excluded, and quarantined labels, plus sample ids of quarantined rows
- `data/reports/dataset_statistics.json` — files kept, characters, token lengths, repositories, language shares

Until those files are generated from a real run, the frequencies in this document remain a partial-index estimate.
